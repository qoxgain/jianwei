# P0.3.5 后续：固定视角独立研究验收

主线 A 顺序保持：可靠冻结特征 → 独立时序学习 → 语义增强。P0.3.5 补齐研究协议、会话统计和工程保护；真实学习尚未验收，P0.4 尚未准入。

## 1. 保留版本与现场记录

读取 `AGENTS.md`、P0.3.5 交付、`docs/RESEARCH-PROTOCOL.md` 和本任务书。保存实际代码、配置、知识、数据清单、正式编码器及其导出记录的哈希。已有九段开发录像、SOP 和历史报告不覆盖；短片的稀疏/密采样是两个特征版本，不是两个独立采集会话。

先确定一个固定机位和稳定视角的研究问题。现场提供带时区的原始采集时间、物理机位、稳定视角、独立会话、日期/班次/人员/生产实例记录，以及原片、派生关系和近重复核查。移动、遮挡和镜头切换按真实证据标注 excluded/unreviewed；未知值保持未知。7 个工业工位不自动组成同视角重复样本，`test` 与 `testShort` 的关系不能根据文件名推断。

## 2. 预登记协议与样本量

先在开发资料上确定采样、历史窗口和预测跨度，然后固定 `temporal.research_protocol` 及 `temporal.dataset_manifest`。主要指标、双对照、相对改善阈值、会话下限、bootstrap 设置由实际研究负责人事先确认；Codex 不替人登记通过或虚构采集审查。

运行下限仍是 2 train + 1 calibration；新的区间验收要求 test 会话数至少满足预登记下限（该下限不能小于 2）。这个最小数量只是软件约束，远不是充分统计证据。应根据研究问题及独立日期、班次和操作实例规划更多会话。若实际只有一个独立测试会话，不通过降低下限或切片制造置信区间。

相同会话的原片与转码仍在谱系中登记，协议只选择一份规范输入。各视角单独研究；train/calibration/test 在采集会话和原始根层面互斥。现有九段已看过的开发录像不再用作新的封存验收。

## 3. 正式提取与准入

使用受信任的官方预训练导出流程、正式冻结 ONNX 和已登记配方，逐来源重提特征。保留原片 SHA、实际缓存 SHA、编码器/预处理/采样/ROI/特征空间、资源与失败记录。不同版本缓存不混用。

运行协议预览、开发来源采样检查和数据库研究准入。封存测试不能在模型与协议固定前用于窗口诊断或选择参数。工程准入仅说明契约满足，不能当作学习结论。

## 4. 一次封存评估及失败保留

仅用 train 拟合归一化/PCA/聚类/小模型，用 calibration 选择候选。下载冻结 `protocol.json`、模型元数据、权重、校准报告及预测日志并核对哈希。

模型和研究协议固定后，显式提交完整预登记 test 名单。报告每个独立会话、每个跨度的 MSE/余弦/NLL/Brier，配对会话 bootstrap，以及相对 persistence 和 shuffled_ridge 的区间下界。只使用事先固定的门槛，不从 test 结果重选模型或阈值。

封存测试已读取后的失败不会释放数据；保留失败原因和消费审计记录。修订模型、协议或采样须另采新的封存数据，不能删除数据库绕过。数值 `passed` 还需审查独立性、数据代表性与失败案例，不自动激活模型或进入 P0.4。

## 5. SOP 与下一阶段

现有工业视频和 SOP 继续用于章节来源定位、工位对应关系和人工审核流程回归。规范、观测、预测、人工结论保持分离；扭矩、电性能和安规结果需要仪器证据。SOP 批准映射不生成动作真值。

只有独立时序研究及其边界经复核后，再提出 P0.4 少量人工正反例、语义锚点与状态记忆任务。没有新录像时可以修复已发现工程缺陷、核对记录和交付缺项清单，不扩大到 RTSP、生产鉴权、自动 SOP 判罚或用合成结果替代现场效果。

交付包含可查看 Demo、代码/CI 链接、数据与协议哈希、实际测试报告、浏览器桌面/手机结果、失败原因和待补现场输入。未经授权不公开新增原片衍生画面。

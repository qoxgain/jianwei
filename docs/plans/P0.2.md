# P0.2：可审计的数据接入

本步承接 `29690eb` 的 P0.1.1，并以[实际浏览器补验](../delivery/p0.1.1-browser/README.md)通过为启动条件。用户当前没有现场数据，因此先交付真实的文件接入能力和明确标注的合成示例流程。

## 交付范围

1. MP4、NPZ 流式上传；服务器生成文件 ID，校验实际字节、限制大小，不接收任意服务器路径。
2. SQLite 持久导入任务，支持幂等提交、重启恢复、失败重试和清单下载。任务保留配置与知识哈希，配置改变时不悄悄重跑旧任务。
3. 读取视频原始 PTS，实际解码并记录亮度、对比度及帧完整性。缺口和 PTS 重置形成独立时间域；采集 UTC 必须有外部提供的带时区锚点。
4. 按场景验证来源绑定、上下文类型、周期策略。零动作、零 SOP 场景同样可用。跨周期或跨时间域的样本不可用于未来配对。
5. NPZ 仅接受约定数组，禁用 pickle，约束解压体积、数组头、维度、行数和有限数；编码器文件仅用于计算指纹，不执行上传的模型。
6. 可选服务器配置的冻结 ONNX CPU 适配器；特征空间记录实际模型文件与预处理、采样、ROI、pooling、维度。无权重明确 blocked，不生成随机向量。
7. 同一租户原始视频的所有场景、ROI、切片共享来源分组，拒绝训练/测试冲突。没有原视频可核验的预计算特征保留来源声明，只能保持未分配。
8. 四场景数据接入页面，支持一键运行服务端合成示例、文件导入、任务状态、清单查看与导出；自包含 HTML 仅回放已实际生成的示例记录，清楚说明运行边界。

## 验收证据

- 原有知识、迁移、前端与机制参考回归；新增导入安全、持久任务、时钟、分组和冻结适配器测试。
- 用 FFmpeg 测试图生成的 MP4 验证实际解码，使用解析 ONNX 测试图验证 CPU 特征计算；两者均不能证明现场识别效果。
- API 与独立演示的实际 Chromium 桌面/手机回归，记录截图、页面异常及控制台错误。
- 本步最终代码与演示同步 `codex/p0-1-foundation`，保留历史版本，不合并 main 或部署生产。

## 下一步门槛

P0.3 在本步功能确认后开始：匿名状态、变化点、未来特征预测与时序基线。没有真实数据和语义真值时，不能把合成指标作为识别率或学习收益。当前不实现 RTSP 在线服务、生产鉴权、教师标注、模型训练、动态 SOP 合规或发布。

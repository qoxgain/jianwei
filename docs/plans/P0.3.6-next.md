# P0.3.6 后续：独立数据准入与可证伪时序研究

P0.3.6工程和回顾性工具已完成；既有九段视频不是新独立证据，正式验收与P0.4保持blocked。完整结果见[交付](../delivery/P0.3.6.md)。不要重复工程验收或整分支合并探索代码，不根据旧holdout挑选新参数。

1. 采集前使用 `python -m scripts.plan_independent_collection --view <稳定视角ID> --output <新草稿.yaml>`。物理机位、安装/方向/ROI、日期时区、班次、操作人员匿名编码、原文件SHA、完整会话和业务周期分别记录；未知保持pending。示例2train+1cal+2test只是最小槽位，不保证统计效能。为不同日期/班次/操作者保留更多独立重复。
2. 按固定视角分别建研究，不把工位1–7当同一工位重复。原片、转码、截取和同源片段保留根/父谱系；只读 `--review-manifest` 检查身份冲突及近重复审核记录。工具不读取封存像素、不因不同SHA自动批准独立性；在正式开发集上可另开展经审核的视觉近重复方法。
3. 按P0.3.5既有准入流程人工确认来源，再登记完整分区、固定producer-v2/编码器/采样、候选、超参数、评价及会话门槛。先对训练/validation研究，有可检验假设再冻结；最终测试全程不用于选择。
4. 算法候选限于有证据的小改动：比较带绝对当前状态的残差与静态回归控制；使用相同结构的history masking检验历史长度；保留Persistence/TrainMean/Ridge和所有负对照。旧holdout可做回顾性调试，但不能成为新的无偏验收。没有新数据时不再在旧八组反复搜索后宣称泛化成功。
5. 取得新的封存来源后按原协议一次评估：按独立会话比较、报告每来源/跨度/退化和置信区间，不把随机种子当独立样本；未稳定胜简单基线则保留简单基线。达到正式门槛后才讨论P0.4人工语义锚点，不自动开放准入。
6. 若原SQLite失败副本可得，先保存原字节和侧文件，仅在新工作副本运行 `scripts.inspect_sqlite_copy`；保留原库、消费状态和研究日志。核对进程退出、可用空间、挂载/锁和I/O日志，未复现前根因保持未确认。不从备份恢复封存测试的“未消费”状态。

现场尚需提供：稳定机位/视角、不同日期/班次/操作人员的独立完整会话、周期/场景审查、根/派生关系及近重复结论；原数据库故障证据（如可取得）。敏感原片、特征、权重和数据库不公开上传；仅提交经审查代码、标量统计和无媒体Demo。

# P0.2衔接：通用视频与特征输入

状态：以下数据契约已经实现并生成Schema；视频解码、特征提取和存储流水线未实现。

## 场景与行业解耦

P0.2读取 `config/system.yaml` 的scenes注册，使用source_id和原始source_hash标识输入，允许没有已命名动作、状态或SOP。scene表示分析目的，不等于摄像头。服装款式、工单等放context，并由该场景context_schema校验；通用Episode不要求它们存在。

类型入口：`packages/contracts/learning.py`。Schema版本统一3.1。

| 契约 | 核心约束 |
|---|---|
| Episode | tenant、scene、source、source_video、source_hash、episode、entity可空、非空PTS区间、context |
| FeatureSpace | 编码器实际权重SHA、预处理SHA、采样SHA、ROI策略hash、pooling、维度；规范化JSON计算完整hash |
| FeatureBatch | Episode + FeatureSpace描述与hash + quality/vector_uri/split/data_origin；向量尚未读取 |
| ActivityObservation | visual_observation、动作可空、UNKNOWN/REVIEW_REQUIRED/VERIFIED、证据及标签层级 |
| StateSnapshot | observed_state；匿名簇必须绑定cluster_version，不能直接等同中文动作名 |
| EventOccurrence | 独立事件ID与核验证据；不是流程节点 |
| Prediction | empirical_forecast；输入截止≤发出时刻<目标开始<目标结束；不含未来观测字段 |
| NormativeExpectation | normative_expected；绑定人工认可workflow与knowledge hash，不是预测目标 |
| MemorySnapshot | tenant+scene+feature_space+knowledge；候选/激活/撤销分离，激活须关联评估 |

`assert_compatible`拒绝跨租户、场景或特征空间检索配对；同为512维不表示兼容。`assert_future_pair`进一步要求同源、同视频内容、同episode、同实体和train分区，且目标窗口在发出预测之后。

## P0.2必须新增

1. MP4与NPZ导入。NPZ用allow_pickle=False，拒绝非法dtype、NaN/Inf、维度/行数不符；NPZ导入不依赖GPU。
2. 独立数据清单，保留真实source_hash、来源路径脱敏引用、PTS、episode、视角、质量和不可跨越的缺口。重复导入幂等，错误返回可诊断原因。
3. 冻结编码器适配器；缺真实权重明确blocked，不生成随机特征。特征空间SHA取实际文件，不接受仅名称声明。
4. 对齐源视频PTS与采集UTC时钟；断流/重置PTS开新时间域，不跨域预测。
5. 不同scene若引用同一原始视频，拆分器必须把它们视为同一来源组，不能一份训练一份测试。所有衍生ROI/切片继承同一父源身份。
6. 将episode_policy与context_schema真正用于导入验证；本期只实现了它们的配置契约。

## 后续研究的成功条件

P0.3先比较持久性、打乱时间、ridge及TCN/GRU。训练只读取train；归一化、聚类器和簇语义映射不得在测试集拟合。状态持续性预测与下一事件预测分别报告。

P0.4—0.5引入冻结教师候选语义和少量人工锚点，独立记录预测错、证据不足、实际不合规。P0.6—0.7进行小模型候选训练与抗遗忘评测。无可靠框不训练YOLO；预测损失下降不直接等同于动作识别准确率提高。

完整发布绑定：config_hash + knowledge_hash + feature_space_id + memory_version + predictor_version + student_version + evaluation_protocol_version。发布器、训练器、实际动态SOP执行均不属于P0.1.1。

# A1 / R01 封存媒体门控

固定基线6a3b3c7的隔离反例已执行：探索422、原片Range206、兼容预览200。仅用生成测试图视频，未访问真实封存数据。证据将随阶段A汇总发布。

统一门控涵盖导入原片/预览、SOP目录媒体/预览、GET/HEAD/Range及异常Range；在完整性哈希、PDF读取、转码与缓存读取前按租户/场景、当前来源分区、请求/清单分区、原始根/父谱系与同会话关系校验。通过路径解析和inode检测已登记封存文件的符号/硬链接别名；历史unassigned清单不能覆盖当前test分区。正式评价仍只经既有协议/消费路径，没有新增媒体免检令牌。

延迟发送响应在真正发送前再检查一次，并持有与正常来源分区提交相同的本地文件锁直到响应结束。先获准的读取先结束，封存提交随后发生；先封存则拒绝读取。预览生成同样持锁，缓存命中仍检查原片及衍生路径。普通开发视频保持200/206、HEAD、ETag与既有SOP单Range语义。

新增测试包括无内容I/O拒绝、旧清单/缓存与并发请求、符号/硬链接、原始根谱系、延迟发送、SOP别名、流式发送与封存提交顺序；相关旧播放、SOP和转码回归保留。最终数量及日志见阶段A总交付。

边界：面向当前单机、可信素材存储的demo服务，不是生产身份鉴权；原片同源关系需要已登记谱系，不能识别任意未登记的再次编码内容。管理员直接修改文件/DB且不遵守租约、跨节点或不支持flock的文件系统不在保证内。长播放会延迟封存提交，后续多路负载需独立验收。没有发布工业原片、衍生画面或数值包。

开发服务器补查：旧Vite `fs.allow=['../..']`会将整个仓库纳入静态读取范围。已改为精确白名单，并在raw/asset/import处理之前核查真实路径与媒体/数值/数据库类型，包括public目录解析，防止`?import`模块处理绕过默认原文件中间件。Vite仅提供前端及必要知识/schema/配置；媒体必须经受控API。浏览器专项同时检验GET/HEAD及raw/url/import变体拒绝和正常知识工作台加载。

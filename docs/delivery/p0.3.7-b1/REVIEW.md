# B.1 用户复核顺序（不启动B.2）

1. 下载Demo并按ZIP内说明在本机回环HTTP打开，进入“局部动态研究”。先确认顶部工业汇总与下方“合成素材”曲线有清楚的证据类别区分；无需权重或后台即可操作曲线和复核导出。
2. 在有授权原片的工作区导入私有`artifacts/p037-b1/real-report.json`，再选择`datasets/video_samples/garment_quality/videos/test.mp4`。检查run为`f63bd84ecdf7…`、原片SHA为`a5ba7ed75052…`、主配置36候选。Demo不从GitHub/远端自动取媒体。
3. 随机跳转候选和非候选时间，查看整段原片及尾部0.5秒，不只确认推荐点。重点检查衣物展开、抬起引起的背景入侵与阴影；检查固定手部框是否一直覆盖实际操作。
4. 保留原算法报告不变，填写审核人，逐项确认/修订/删除并补充漏检，人工事件单独导出JSON。没有完整审核0—118500ms时不要勾完整覆盖，不计算Recall/F1。复核事件必须与源、配方和run一致。
5. 修改ROI只生成新配置草稿，要写入新runtime的system.yaml后重新提取到新目录，不得改历史曲线。原受污染背景结果仍保留。另选背景属于后验新实验，需要独立记录。
6. 用`analyze_b1 --review`产生新报告并载入；固定容差500ms，只评时间边界。若标注已被候选提示，评价标记candidate_assisted。真正独立标注不能引用算法候选。
7. 对照所有4个窗口/密度、3阈值、3平滑，不按候选数或幅度选择“最好模型”。当前无法证明局部R3D优于帧差，不将单源开发结果当独立泛化。
8. 用户和独立复核方决定B.1结果是否足以开展下一阶段；本交付不自动启动B.2，也不改变正式科研协议和P0.4限制。

所有工业原片、逐窗口报告、特征和模型留在授权环境。可公开的是经过审查的代码、汇总统计、没有工业画面的合成Demo及工程证据。

# 合成CI冻结导出版本兼容修复

第一次官方编码器任务在apt阶段迟滞，人工请求取消后重新执行；保留取消记录。重试的9项编码器测试和官方checkpoint转换检查通过，但B.1原有精确哈希检查拒绝了导出文件。

历史主模型：`2979019509005056778db9f462e9eed212c40f02d5e5bf1d6fc9e06caf2ebab8`。

本次本地及CI均重现：`36408854debf56e529e1fdafceb0d2dc27e03e230ef4fe5eb034828779f8f141`。

图结构（移除initializers后序列化）完全相同；差异在Conv/BN折叠常量，观察到最大绝对差2.384185791015625e-7。新的转换对框架最大误差1.5497207641601562e-6、重载误差0、官方预处理误差7.152557373046875e-7，在原固定1e-4转换容差内。数学数值接近不等于同一缓存身份。改变ATEN默认/avx2选项都未恢复旧哈希，具体底层工具链/实现差异成因未确认，不归因于某一CPU或SQLite。

因此不改原哈希、不把新文件改名为旧模型、不上传任何权重、不用近似误差放行任意模型。只为**生成素材的工程CI**注册上述精确的新哈希：

- 现场开发视频和旧真实缓存仍只接受297901…；364088…在现场路径必须拒绝。
- 生成素材仅接受上述两个明确注册的哈希；仍核验实际文件SHA、官方导出回执、冻结状态和原始预处理版本。未知/改动字节一律拒绝。
- runtime配置、生产配方和缓存记录实际哈希；所有新特征生产代码变更形成新配方身份，不覆盖旧缓存或历史v1—v4配方。
- 生成模型变体和旧模型不能混用原型空间：跨来源特征契约要求encoder_sha256相等。合成来源不能改充现场独立泛化证据。
- B.2-U工业数值始终来自旧B.1缓存/主模型。合成CI可使用新导出，分别记录来源和生产版本；不会重算工业曲线或更改研究门槛。

新增已注册版本/未知版本/现场拒绝/跨空间拒绝回归。旧B.1视觉算法、PTS和ROI数学未重写；只补固定版本准入和配置工厂，解除CI对不可逐字复现导出的错误隐式假设。

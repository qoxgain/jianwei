# A4-02 备份生命周期与业务准入

业务身份v1分为：SQLite内部受保护身份表（UUID、Active或Backup、规范路径绑定）、原子持久化的业务登记（device/inode/UUID/路径）、可选文件系统生命周期标签、备份操作回执。文件后缀和相邻回执不是唯一权威。新业务库只能在原路径不存在时受控初始化；连接建立前在提交闸门之外完成准入，提交路径只做轻量文件身份/登记核查，不等待新的SQLite读取锁。

备份刚创建就标为Copying；复制完成关闭连接后，在副本内部写Backup身份，再做Validating、源与副本完整性校验、SHA和Published。故障/异常/取消保留Invalidated/Failed/Cancelled回执；备份请求可另建RecoveryPending审核记录，但本轮没有恢复批准或自动覆盖业务库接口。内部身份跟随文件复制：完成产物即使改名、去除xattr也不是Active；复制中若仍带源Active身份，路径绑定不同而拒绝；空或未知部分文件必须离线审核，不能自动视为新库。xattr不支持时仍有内部身份/默认拒绝，不靠后缀保护。

Published备份只读校验正常，不能通过业务Database/Session/migrate或legacy登记入口取得写资格。RecoveryPending不改变原归档字节/回执，也不重开任何已消费test。普通业务SQL不能修改内部身份表。源身份、隔离意图与业务登记联合验证；原路径被归档替换仍先遵守不可清隔离。

没有身份元数据的历史文件，在信息上无法仅凭字节区分旧业务库与旧备份。兼容采用明确停写、具名审核、精确SHA及消费台账复核后登记，不自动接纳未知文件。这是有意的准入变化，需独立审核确认，不宣称无条件零操作升级。旧业务表/ID/内容保持，追加内部登记后执行原Alembic迁移；误匹配SHA和任何已识别备份拒绝登记。元数据缺失/不一致不自动重建，进入待离线处理状态。

离线示例（请使用自己的配置和真实审核信息，不在本任务运行客户库）：

```bash
.venv/bin/python -m scripts.register_sqlite_legacy --config config/system.yaml --profile demo --reviewer NAME --reference TICKET --expected-sha256 SHA256 --writers-stopped --consumption-reviewed --legacy-business
```

初轮18个既有用例因未登记的生成旧库而失败，未删除断言；为这些旧业务夹具显式提供审核步骤。其后DELETE并发出现一次身份读取零超时错误，已改为配置的有界SQLite等待，发生在提交闸门之外，BUSY不永久隔离。修复后124项隔离/备份/保存点/原生目标/迁移相关回归通过；进一步新增无xattr、隔离交叉、登记丢失与RecoveryPending验证。原始失败日志保留。

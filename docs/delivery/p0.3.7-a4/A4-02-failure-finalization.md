# A4-02 失败返回前的身份收尾补充

579bacb候选CI期间补充生成反例：最后一页取消时SQLite已复制完整Active身份，但异常绕过正常mark_archive。关闭源连接后，手工原位复制partial回原规范路径/inode（控制记录未变），新受管写入可提交。它涉及外部裸替换，但不能用“没有恢复接口”掩盖这一正常失败返回产物仍含Active身份的缺口，before实际结果保留。

修复仅操作本次新建、已关闭的staging：先将未改动原始SQLite及WAL/SHM/journal字节和SHA封装到非数据库证据ZIP，再给可用staging写Backup身份。已经是Backup则不重写。不能安全编辑的坏/被锁文件在原路径替换为无损证据容器，不再是可写SQLite。正常Published路径、源业务表和正常备份语义不变；失败原始字节在容器中保留，不在历史损坏原件上运行。发布中发生异常时先撤销本操作未确认的目标链接，再修改staging，不触碰他人/历史备份。

证据容器与partial使用独立命名空间，避免枚举误把ZIP作为SQLite；初次相关12个失败由该命名碰撞导致，保留日志，未删除断言。修正后新增5项与旧准入/备份/保存点共78通过：取消、异常、中断的最后一页，原位复制后拒绝，损坏staging无损封装，以及封装存储失败安全停止。证据SHA与原始字节分别核对。

失败收尾使用既有backup.timeout_seconds作为独立有界清理预算；总失败响应可能包含复制预算加收尾预算，可信回调/卡死内核I/O不在可抢占保证内。若证据存储/封装也失败，关闭产物访问并持久化源admission_safety_stop，明确停止服务离线处置，不把它误称为SQLite物理损坏。普通SQLite读取竞争可转为证据容器，不单因BUSY误判源物理损坏。

强杀发生在复制过程中、尚未来得及失败收尾时，残留Copying依赖生命周期与源路径绑定拒绝普通新路径准入。管理员在此时抽取原始字节、保留同一逻辑路径/inode并绕过控制记录裸覆盖，不属于受支持恢复接口，也不声明有外部单调台账的严格防回滚保证；这仍需权限隔离和离线恢复审核。原始证据容器的人工解封同样不批准恢复。若验收要求覆盖这些管理员原位裸恢复，应继续阻断正式准入而不是宣称不存在竞争。

# A4-03 完整检查与故障阻断分离（架构决策待独立确认）

配置统一入口仍为system.yaml的sqlite。新增commit_integrity_check=full|fault_state，默认full保留A.3逐写事务完整检查；旧配置快照不补入未显式设置的新字段，历史配置/特征身份不因默认值漂移。fault_state必须显式选择，仍检查不可清持久意图、正式fault、数据库/登记身份、事务与保存点约束及authorizer；不移除提交闸门、FULL同步、异常检测、连接完整预检或备份源校验。

新增integrity_check_interval_seconds（默认0，不自动巡检）。应用启动可按配置启用独立完整巡检线程；查询SQLite与等待BUSY发生在提交闸门之外，异常分类不把BUSY/LOCKED/超时视为物理损坏。巡检关闭有取消/进度与有界join，故障意图出现后不自动恢复。健康接口显式返回策略、实际巡检次数、最近异常和无保证的发现延迟。

正式研究排队/保留test前、研究执行读取特征前、封存消费标记前都强制完整check_integrity，不用quick_check替代；备份仍在原强制节点完整校验。连接建立与旧库审核亦完整检查。真实CORRUPT/NOTADB/IOERR/FULL即时走独立持久意图，阻断不等巡检。

保证变化：fault_state不再保证每次写提交尝试检测全库结构。损坏未发现时，缓存连接仍可能继续提交；发现延迟取决于下一次成功的启动/连接/边界/巡检或SQLite异常。即使配置周期，也不能在持续BUSY、扫描超时或系统调度受阻时声明严格时间上界。所有已确认故障立即禁止新提交准入；更早已准入native COMMIT的排空边界见A4-01。此策略不是与full完全等价的安全证明，是否用于现场须独立审核确认；本轮不自动切换根配置或启动生产服务。

性能比较使用相同生成布局、同步等级、SQLite缓存、客户端与负载：固定fb69646 A.3为主对照，固定6429844 A.2为79MiB辅助对照，A.4 full为79MiB加固成本对照，A.4 fault_state显式开启1秒完整巡检。测量热连接持续写吞吐，单列登记/连接启动、全量检查、CPU/RSS/进程I/O与备份实际重叠时间；不把一次短跑p99当生产SLO。所有案例/失败保留，后续性能结果报告具体值，不预设显著收益。

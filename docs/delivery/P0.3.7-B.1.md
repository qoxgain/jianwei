## 2. 实现与可追溯配置

- `packages/contracts/local_motion.py`及`system.yaml.local_motion`是统一配置入口；旧场景未启用时快照不新增空配置，保留旧接口和哈希兼容。
- `packages/local_motion/extraction.py`复用有界解码、旋转/SAR几何、原始PTS、官方R3D输入和冻结ONNX。只准入已登记开发源或本地生成回执，读取媒体前拒绝test及同源test。
- 官方R3D-18/Kinetics400，512维、CPU，ONNX SHA `2979019509005056778db9f462e9eed212c40f02d5e5bf1d6fc9e06caf2ebab8`。没有重新训练编码器，也没有解析编码器替代。
- `motion.py`纯NumPy连续采样帧差及32×32灰度块匹配，8像素块、半径3、纹理/匹配改善筛选。它是廉价平移运动估计，不等价于高精度光流、手部检测或动作语义识别。
- 每个ROI记录坐标、显示尺寸、时间范围、可见性/排除区间、采样参数、实际帧索引与PTS、固定16帧输入的重复索引、模型和生产依赖哈希。空/越界ROI、显示尺寸变化、PTS覆盖不足和解码异常明确失败/排除。人工标记严重遮挡会排除；自动亮度检测不能发现所有语义遮挡。
- 全局/局部R3D用相邻有效窗口余弦距离，缺失不跨空洞连接。运动按同一片段、实际采样间隔归一化；不同fps的帧差仍可能因运动混叠变化，不能认为数值完全可互换。
- 前20%时间前缀中位数/MAD拟合，固定尺度下限1e-6、z裁剪±100，保留全部曲线及饱和；时间平滑为**离线中心平滑**。候选需等支持窗口/平滑未来邻居到达后才可计算，不宣称因果实时性能。
- 生产配方、依赖/工具版本见[实际特征配方](p0.3.7-b1/feature-recipe.json)，工业曲线/NPZ仍私有。新版本只写新目录，不重标历史缓存。

## 4. 负结果、研究问题与人工复核

回看原始片段：约88秒衣物展开进入右下“背景”框；69秒附近明显光照/阴影改变。背景帧差出现强响应及z=100饱和，故**本轮背景负对照受污染**。原ROI及全部结果保留，不在看过结果后悄悄换框重跑。后续应先人工审核背景有效区间或预登记新ROI，再单独记为后验追加实验。

1. **局部更明显吗？** 多种局部描述有动态响应，但幅度更大不证明边界更清楚。只有一次单源描述证据，尚不能做肯定的准确性结论。
2. **能区分相邻工步吗？** 没有完整人工工步/边界，blocked。候选类型仅表示表征变化/运动起落/峰值，不能直接当动作起止或停顿语义。
3. **能减少背景干扰吗？** 当前相关仍.49—.62，背景有衣物侵入及阴影；尚未证实。保留失败案例而非宣称完成负对照。
4. **遮挡/视角/偏移敏感性？** 轻量偏移完成两个配置；深度偏移及实际遮挡/跨视角验证未执行。无效帧/人工遮挡排除机制已测，不等于真实鲁棒性已测。
5. **深度特征较帧差增加什么？** 两者候选仅部分重合，证明响应不同；13/33/10不是增益证明。没有真值与标注成本对照，R3D附加价值未验证。
6. **B.2建议？** 先以便宜帧差/块运动为可审计候选基线，保留冻结R3D对照。用户完整审核36候选及范围内漏检、确认干净背景后，再决定是否允许B.2；本轮不自动进入。

人工confirm/adjust/delete/add事件与预测分开，绑定源SHA/recipe/run。仅确认推荐点不产生Recall/F1；必须声明完整时间覆盖、审核漏检并完成范围内决策。固定±500ms一对一时间匹配，不评价动作类型；候选辅助标注仍存在提示偏差，不能当独立泛化。独立标注模式不能引用算法候选。真实工业人工边界数量仍0，**F1=null**。

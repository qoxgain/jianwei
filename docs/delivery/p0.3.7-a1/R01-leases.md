# R01-2/3 租约与封存状态

基线在AnyIO容量2时复现：两个锁等待者占满共享线程，已授权同步媒体流无法取线程继续；容量4恢复。另复现test请求排队后SourceSplit仍unassigned，取消后却继续422。

整改：文件锁等待采用LOCK_NB与异步轮询，等待期间不占AnyIO工作令牌；HTTP/SOP操作在进入同步工作前先异步取租约，再将已持有租约传给有界同步调用。同步后台封存等待也不再持进程内锁阻塞异步持有人。取消、超时或发送异常始终释放锁描述符；不增加线程池容量。

media_access可选统一配置：HTTP等待默认5秒、后台正式提交等待30秒、轮询0.01秒；超时503且不读取媒体。合法旧配置无该字段时仍可加载，不改变历史快照。新增只读media-admission端点，返回development/pending_seal/sealed/seal_failed/cancelled及当前普通访问判定。

一致性：入队DB提交是待封存意图生效点，立即阻止新的媒体授权；此时已完成授权的流可继续（不撤回既有字节），正式SourceSplit=test必须等其租约结束再提交。已有流之前的授予点与pending之后的新请求区别明确。取消与失败消除该请求的pending意图；别的pending或既有sealed仍优先阻断。重试重新pending；取消成功封存任务不会unseal。未通过延迟准入保护或放行正式test解决竞争。

71项相关回归通过：容量2与六等待者正常完成、等待不借工作令牌、有界超时、取消、真实FileResponse关闭文件/锁、HTTP解析不走同步锁等待、pending/失败/取消/重试、已有授权与正式提交屏障顺序以及旧媒体/SOP/导入。实际客户网络、跨节点、不可靠flock文件系统仍未验证。

# A3-02 损坏源与在线备份边界

备份在开始复制前、复制校验后和发布前独立复核源结构完整性；临时BUSY/LOCKED按截止时间轮询并报告实际状态，不在等待SQLite锁时持提交闸门。最终短闸门内再次检查不可逆隔离状态，确认损坏后无法发布有效备份。A.2的DELETE/WAL反例保留。

副本校验与源校验分开：只有副本损坏不证明源损坏；已损坏源则由统一完整性机制持久隔离。复制异常在资源展开后复查源，原始异常类型保存在回执。失败副本仍保留partial，已隔离源的操作标记invalidated。先完成published、后出现故障的历史备份不删除、不改状态。

新增phase_observer提供before_copy、after_copy、after_validation、before_publish屏障，均在SQLite连接和提交闸门之外运行。用于可信短时观察/故障调度，不可无界阻塞或修改副本内容；截止保证不涵盖恶意回调或卡死内核I/O。

备份创建不是恢复批准：带操作回执的备份目标不能直接作为可写业务Database，报DATABASE_RESTORE_REVIEW_REQUIRED；只读取证可在隔离工作副本进行。同逻辑原路径的旧文件覆盖也不能清除独立隔离状态。任意管理员复制文件并剥除控制证据的跨位置恢复不是支持接口，必须离线核对封存消费台账，不宣称可自动证明这类恢复安全。

8项新增真实SQLite测试及相关旧回归共65项通过：未预检查的损坏源、四个阶段确认故障、校验后源损坏的自动发现、目标单独损坏不误隔离源、历史备份与消费记录保护。旧DELETE/WAL、原生目标/row_factory、事务与迁移继续通过。

# A.2 R01 优化依赖的可信输出边界

攻击面仅指自有项目的可写优化缓存/metadata；应用源码、明确受审清单、锁文件、安装依赖、打包器及进程内存为可信。任意本机执行、管理员修改可信根不在本轮威胁模型内。开发服务仍默认loopback；正式部署不得让Vite开发进程挂载正式封存数据、工业特征/权重或生产数据库，上传也不得使用node_modules缓存目录。

原实现把metadata成员名称及其源文件摘要当作派生产物的授权依据，不能发现成员内容替换。新实现明确列出九个实际依赖入口，禁自动发现并强制重建；由可信Rolldown的generateBundle钩子在写入缓存磁盘前，直接对内存中的实际JS及source-map输出形成摘要和只读响应副本。缓存metadata、同目录摘要或文件名不能自行增添授权。

普通模块访问每次核查当前文件的独立普通文件/路径/SHA，且直接从已核验的内存输出发送响应；不会校验后交给另一次磁盘读取。仅开放ES模块及调试map所需GET/HEAD和正常v/t/import查询；缓存的raw/url、未知查询及Range不属必要模块接口，明确拒绝。合法map带SourceMap关联头。可信清单以原子写入更新，审批的客户端修改通过Vite实际HMR通道刷新；未审批变更不自动发布。

R02将故障闸门放在实际DBAPI提交，并覆盖CPython原生isolation_level/autocommit赋值、直接SQL COMMIT/END/RELEASE。共享故障标记在DB外只创建一次；不完整也隔离，重启与旧DB备份覆盖均不自动清除。故障期间新事务拒绝，任务停止，HTTP503，不依赖同一故障DB写终态来虚报完成。authorizer覆盖注释/CTE写入空间检查；隐式脚本提交和blob直写等不受管路径明确拒绝。

R03新生产采用 `p037-feature-production-v3`；历史v1/v2清单、哈希、缓存与模型保持原样，可读回查但不冒充当前正式配方。既有入队/执行/提取前后/幂等与正式协议边界重新核验实际工具内容和版本。



后台故障测试另建临时DB，不提供HTTP故障注入或解除隔离端点。结束本机服务使用Ctrl+C。请以实际导出的结果、兼容播放及审核反馈确认A阶段；**未收到用户通过反馈前不执行B阶段**。

## 尚未验证与边界

- 原 `database disk image is malformed` 历史损坏根因仍 **未确认**；本轮确认修复的是可复现的“已记录故障后仍提交”缺陷。
- 提交/媒体租约适用于同机、规范化路径、受管理连接和可靠本地flock/SQLite文件系统。管理员直接改库/删标记、非受管理sqlite进程、硬链接DB身份、复制旧备份到新身份、NFS/SMB及跨节点不在保证内。**未实现任意外部恢复下的全局消费账去重**；没有自动恢复工具，不能通过外部恢复把已观察数据重新封存。人工恢复前需保留原库/侧文件/隔离证据并离线核对消费水位。
- 如果磁盘连隔离标记和fsync都无法写入，只能保证本进程内存隔离，跨进程持久性不可声称成立。断电、硬件I/O和客户现场负载未验收；多线程fork不作为安全启动方式。
- 来源谱系依赖登记；任意未登记转码内容和管理员恶意热替换不可能仅靠声明自动识别。新工具核验关闭mtime缓存盲区，但不是不可变系统/共享库部署证明。
- 无新增现场独立数据，无动作边界/局部特征/匿名原型研发或科研验收。P0.4继续blocked。

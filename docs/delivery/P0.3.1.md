## T1：有界解码

第一遍顺序扫描全部原始帧，核验 PTS、帧数和质量；第二遍只保留当前采样窗口。保留原采样策略、质量门槛和时间域，不再生成整段 `decoded.rgb`。失败、缺模型和 NPZ 来源核验路径都会关闭帧读取器及 FFmpeg 子进程。

[实测对照](p0.3.1/decode-comparison.json)使用相同视频和原默认 224 输入/224×168 解码尺寸；旧版为允许其完整展开，显式使用 512 MiB 临时预算，新版使用原默认 128 MiB。2,844 帧 PTS、持续时间、逐帧质量、时间域/周期及 117 个采样张量逐字节摘要全部一致。

| 实测项 | 旧版 | 新版 |
|---|---:|---:|
| RGB 临时磁盘 | 321,076,224 字节 | 0 |
| 采样峰值 RSS（工作进程与子进程合计） | 411,578,368 字节 | 143,273,984 字节 |
| 本次耗时 | 29.07 秒 | 52.58 秒 |

RSS 约下降 65.2%。Linux `/proc` 每 10ms 采样，合计共享页可能重复计数；这是解码对照，不包含正式模型权重。共享云主机上的耗时仅作本次记录，双遍处理存在时间开销。128 MiB 是解码活动缓冲/张量预算，不是整个 ONNX 服务的 RSS 上限。自动测试覆盖超时长、超帧数、单帧/采样窗口预算、重叠采样、反向读取、源替换与清理。

默认配置现可完整解码本视频，随后因缺编码器明确 `blocked`；解析式诊断图仍得到 117 个片段，见 [诊断复测](p0.3.1/diagnostic/real-video.json)。诊断图不作为预训练模型。

## T2：正式冻结编码器

使用官方 torchvision `v0.22.1` 的 `R3D_18_Weights.KINETICS400_V1`，完整加载预训练参数后移除分类头，冻结全部参数，输出 512 维。CPU PyTorch `2.7.1+cpu` 导出 ONNX opset 17。来源、许可边界和安装步骤见 [正式模型说明](../PRETRAINED-ENCODER.md)。checkpoint/ONNX 大文件留在忽略目录，通过固定 URL 和 SHA 复现，不把随机权重当预训练模型。

输入为 `float32[N,16,3,112,112]` RGB `[0,1]`；使用官方 bilinear 128×171、center crop 112×112，均值/标准差归一化封装在图内。原主配置不变；真实验收配置明确设 `decode_width=640`，保留原图后执行官方模型变换，仍使用 128 MiB 活动缓冲预算。

| 转换检查 | 实测 |
|---|---:|
| 框架/ONNX 最大绝对误差 | 1.5497×10⁻⁶ |
| 与官方预处理最大绝对误差 | 7.1526×10⁻⁷ |
| 重载输出差 | 0 |
| 两个真实片段表征 L2 距离 | 12.1628 |

两个片段只是转换诊断，仍来自一个视频。缺权重、错误 SHA 和错误输入契约都有阻断测试。

## T3：真实单视频结果

`test.mp4` 完整 118.5 秒、640×480、24fps、2,844 帧。真实 API 导入保持全源 `unassigned`；重复提交返回相同任务。正式模型生成 **117×512** 有限且非恒定的特征，本次耗时 352.241 秒。解码缓冲保守分配上界 85,315,584 字节，RGB 临时磁盘为 0；该上界不等同进程 RSS。

- ONNX SHA256：`36408854debf56e529e1fdafceb0d2dc27e03e230ef4fe5eb034828779f8f141`
- 特征缓存 SHA256：`06cba1e716fd0b73a7087871892e077a0a1f83c38a801336825d01d95534327c`
- 配置 SHA256：`1750729a1d53de09b4340b78890434516c4617bad6943875d691e9a5af6e3b0f`

按既有场景策略，0–60 秒是完整固定窗口，覆盖原视频时间 **50.63%**；60–118.5 秒是尾部不完整窗口，明确排除。固定窗口不等于人工确认的服装业务周期。

在有效特征上做单源回顾性 PCA、聚类和变化点描述，得到 **17 个匿名候选分段**。每段保留原始 PTS、特征行和代表片段，可回查原画面。这些统计量使用整个未分区来源，只用于描述，不保存为独立预测候选、不读取封存 test、不计算动作/边界准确率。
